# Design Decisions (Agent 1 — Backend/Data Platform)

Each entry: decision, reason, consequence. New phases append entries.

## Spec source

The ACADLYTICS Project Blueprint and the Agent 1 work package were not available
when the backend was started. The Agent 1 instruction prompt is the working spec.
Any assumption not stated there is recorded in this file. If the Blueprint appears
later and conflicts with an entry here, the Blueprint wins and the entry is revised.

## D-001 Modular monolith, one package per domain module

`backend/app/modules/<module>/` holds `router.py → service.py → repository.py`
plus `models.py` and `schemas.py`. Routers never touch the session directly; they
build a service through a dependency. Keeps boundaries clear without the operational
cost of services, and lets Agent 2 add its own modules beside ours.

## D-002 Synchronous SQLAlchemy 2.x with psycopg 3

Sync `Session` rather than `AsyncSession`. FastAPI runs sync dependencies and
endpoints in a threadpool, workloads are CRUD and batch imports rather than
high-fan-out I/O, and sync code is simpler to test and reason about for
transactional imports. psycopg 3 keeps an async path open if ever needed.

## D-003 Services own transactions; repositories never commit

A request gets one session (`get_db`). Repositories add/query/flush only. The
service method that implements a business operation commits once at its end, so
multi-step operations (e.g. import confirmation) are atomic by construction.

## D-004 PostgreSQL only, including tests

`DATABASE_URL` is validated to be `postgresql+psycopg://`. Tests run on a real
PostgreSQL database created per test session and built by running the Alembic
migrations (never `create_all`), so tests exercise the migrated schema, real
constraints and PostgreSQL-specific behaviour. Each test runs inside a transaction
rolled back afterwards (service commits become SAVEPOINT releases).

## D-005 Deterministic constraint naming

`Base.metadata` uses a fixed naming convention so autogenerated migrations are
stable and constraint names are predictable in error handling.

## D-006 Migration drift is a test failure

`tests/test_migrations.py` checks: single Alembic head; upgrade from an empty
database, full downgrade, re-upgrade; and zero diff between models and the migrated
schema. A model change without a migration fails CI.

## D-007 `/health` is unversioned and reports readiness

`GET /health` (outside `/api/v1`) returns 200 with the current migration revision
when the database answers, 503 `degraded` when it does not. Suitable for Docker and
orchestration probes.

## D-008 Container applies migrations on start

The API image runs `alembic upgrade head` before `uvicorn`. Fine for a single API
instance. With several replicas, migrations should move to a one-off job.
